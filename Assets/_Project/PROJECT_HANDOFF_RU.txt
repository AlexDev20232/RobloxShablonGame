1. Главная цель проекта

Это Unity-шаблон для быстрых прототипов Roblox-style игр под Яндекс Игры.
Идея проекта: сделать удобную базу, на которую можно быстро наращивать разные популярные идеи из Roblox-жанра:
- brainrot / мемные существа;
- база игрока;
- слоты на базе;
- пассивный заработок;
- прокачка;
- перерождения;
- коллекционный индекс;
- магазины и апгрейды.

Проект не должен быть одной жестко зашитой игрой. Он должен быть удобным шаблоном: чтобы потом можно было заменить тему, добавить новые brainrot-персонажи, новые апгрейды, новые магазины, новые механики и быстро собрать новый проект такого типа.

Важно: лишнюю wave/run-логику нужно убирать. Нужна чистая основа: ходьба, анимации, brainrot-система, база, слоты, доход, апгрейды, rebirth, index, shop.

2. Референсы и жанр

Проект вдохновлен текущими Roblox-играми, где игрокам заходят:
- базы;
- brainrot-коллекции;
- стаки и слоты;
- пассивный доход в секунду;
- прокачка дохода/скорости/силы;
- покупка новых этажей/слотов;
- rebirth с множителем заработка;
- index с открытыми и закрытыми персонажами;
- простой яркий визуал в стиле Roblox/lego.

Примеры референсов, которые обсуждались:
- Wave Brainrot;
- Kick a Lucky Block;
- Brainrot Sniper;
- похожие brainrot/base/progression Roblox-проекты.

3. Основной игровой цикл, который нужен

1. Игрок бегает по локации с управлением, похожим на Roblox.
2. Игрок получает или подбирает brainrot.
3. Игрок ставит brainrot на свободный слот базы.
4. Brainrot правильно разворачивается лицом к базе/передней стороне слота.
5. Brainrot копит деньги сам по себе.
6. На income panel около слота показывается накопленная сумма.
7. Игрок физически заходит в триггер income panel.
8. Деньги с конкретного слота добавляются в общий баланс игрока.
9. Накопленная сумма на этом слоте сбрасывается.
10. Игрок улучшает brainrot за деньги.
11. При каждом уровне доход brainrot увеличивается, а размер/визуал может немного расти.
12. Игрок покупает новые слоты базы.
13. Когда текущий этаж заполнен, открывается следующий этаж и первый слот на нем.
14. Игрок делает rebirth, получает +0.5x к заработку базы за каждое перерождение.
15. Открытые brainrot автоматически попадают в index.
16. В shop можно покупать валюту, предметы или улучшения.

4. Правила пассивного заработка

Стартовый доход brainrot задается вручную в данных brainrot.
Например: первый уровень дает $5/s.

Income panel не считает сложную формулу каждый раз. Она просто хранит накопленную сумму слота и каждую секунду добавляет:

доход brainrot в секунду * уровень/множитель brainrot * множитель базы от rebirth

Когда игрок заходит в trigger income panel:
- накопленная сумма переводится в общий баланс;
- income panel обнуляется;
- слот продолжает копить деньги снова.

5. Brainrot-контент

План: минимум 50 brainrot для нормального шаблона.

Нужно, чтобы добавление нового brainrot было простым:
1. Добавить модель/префаб в папку brainrot.
2. Заполнить данные: id, имя, редкость, стартовый доход, иконку, prefab.
3. Brainrot автоматически появляется в каталоге/index.
4. Если игрок получил brainrot, он считается открытым в index.

Brainrot должны поддерживать:
- имя;
- редкость;
- тип/категорию;
- базовый доход;
- уровень;
- множитель/скин;
- иконку для UI;
- prefab для спавна;
- idle-анимацию или простое покачивание.

6. База и слоты

Нужно сохранить логику:
- по дефолту доступны только первые слоты;
- верхние слоты и этажи закрыты;
- игрок покупает слоты за деньги;
- если на текущем этаже все слоты открыты, покупка открывает следующий этаж и первый слот;
- дальше открываются второй, третий, четвертый слот этого этажа и так далее;
- цены должны быть конфигурируемыми, желательно через ScriptableObject.

Таблички возле базы должны показывать:
- текущий множитель базы, например x1, x1.5, x2;
- цену следующего слота;
- возможно количество открытых слотов и этажей.

7. Rebirth

Rebirth нужен как базовая механика прогрессии.

План:
- rebirth требует накопить определенную валюту/стат;
- после rebirth часть прогресса сбрасывается;
- каждый rebirth дает +0.5x к cash/income базы;
- UI показывает текущий rebirth и следующий множитель.

18. Git workflow для следующего Codex-чата

Перед изменениями желательно сделать backup commit, если рабочее дерево чистое.

После каждой завершенной правки:
1. Run git status.
2. Stage only:
   - Assets;
   - Packages;
   - ProjectSettings;
   - .gitignore;
   - .gitattributes.
3. Always include changed .meta files.
4. Never commit:
   - Library;
   - Temp;
   - Obj;
   - Logs;
   - Build;
   - Builds;
   - secrets;
   - API keys;
   - local credentials.
5. Commit with short message.
6. Push to origin main.
7. If push fails or remote history conflicts, stop and report. Do not force push.

Useful commands:

git status
git add Assets Packages ProjectSettings .gitignore .gitattributes
git diff --cached --check
git commit -m "backup: update project"
git push origin main

19. Важная просьба по стилю кода

Код должен быть простым, чистым и поддерживаемым.
Не нужно усложнять архитектуру ради архитектуры.
Лучший подход:
- данные через ScriptableObject;
- одна понятная система вместо десятков дублей;
- настройки в inspector;
- минимум жестко зашитых значений;
- не вешать одинаковые настройки вручную на каждый объект, если можно централизовать;
- не ломать существующие сцены и материалы без проверки.
